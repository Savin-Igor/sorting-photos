# Асинхронная и параллельная обработка файлов

## Текущее состояние

**По умолчанию** приложение работает в **синхронном режиме**:
- Все файлы обрабатываются последовательно, один за другим
- Используется `SynchronousMessageBus` для немедленной обработки
- Подходит для небольших объемов данных (до нескольких тысяч файлов)

## Асинхронный режим (параллельная обработка)

Для обработки больших объемов данных (2+ ТБ, десятки тысяч файлов) используется **асинхронный режим**:

### Как это работает

1. **Сканирование**: `ScanFilesCommand` сканирует директорию и отправляет события `FileDiscovered` в очередь (Redis/RabbitMQ)
2. **Очередь**: Сообщения попадают в очередь `async` transport
3. **Workers**: Один или несколько worker'ов обрабатывают сообщения из очереди параллельно
4. **Pipeline**: 
   - `FileDiscovered` → `IngestFileCommand` → извлечение метаданных, расчет хэша
   - `FileProcessed` → `OrganizeFileCommand` → копирование файла с сохранением метаданных
   - `FileOrganized` → логирование успешной обработки

### Преимущества асинхронного режима

- ✅ **Параллельная обработка**: Несколько файлов обрабатываются одновременно
- ✅ **Масштабируемость**: Можно запустить несколько worker'ов для увеличения скорости
- ✅ **Отказоустойчивость**: Автоматические повторы при ошибках
- ✅ **Мониторинг**: Просмотр очереди и статистики обработки
- ✅ **Производительность**: Для больших объемов данных обработка в разы быстрее

### Как запустить асинхронный режим

#### Вариант 1: Использование Docker Compose Worker (рекомендуется)

```bash
# 1. Запустить приложение с worker'ом
make up-worker

# 2. В другом терминале запустить сканирование
make run

# Worker автоматически обработает все сообщения из очереди
```

#### Вариант 2: Ручной запуск worker'а

```bash
# 1. Запустить приложение
make up

# 2. Запустить сканирование (сообщения попадут в очередь)
make run

# 3. В другом терминале запустить worker
make consume

# Или запустить несколько worker'ов для параллельной обработки:
docker compose exec -d app php bin/console messenger:consume async -vv &
docker compose exec -d app php bin/console messenger:consume async -vv &
docker compose exec -d app php bin/console messenger:consume async -vv &
```

#### Вариант 3: Множественные worker'ы через Docker Compose

Создайте несколько worker сервисов в `docker-compose.yml`:

```yaml
worker1:
  # ... (копия worker сервиса)
worker2:
  # ... (копия worker сервиса)
worker3:
  # ... (копия worker сервиса)
```

Затем запустите:
```bash
docker compose --profile worker up -d --scale worker=3
```

### Настройка параллелизма

#### Количество worker'ов

Количество параллельно обрабатываемых файлов = количество worker'ов

**Рекомендации:**
- **CPU-bound задачи** (извлечение метаданных, расчет хэша): количество worker'ов = количество CPU ядер
- **I/O-bound задачи** (копирование файлов): количество worker'ов = 2-4 × количество CPU ядер
- **Для 2 ТБ данных**: рекомендуется 4-8 worker'ов

#### Пример для 2 ТБ файлов

```bash
# Запустить 8 worker'ов для параллельной обработки
for i in {1..8}; do
  docker compose exec -d app php bin/console messenger:consume async -vv --time-limit=3600 &
done

# Или использовать Docker Compose scale
docker compose --profile worker up -d --scale worker=8
```

### Мониторинг очереди

#### Redis

```bash
# Подключиться к Redis CLI
make redis-cli

# Просмотреть длину очереди
LLEN messages

# Просмотреть сообщения в очереди
LRANGE messages 0 -1
```

#### RabbitMQ

```bash
# Открыть веб-интерфейс RabbitMQ
make rabbitmq-management

# Или через CLI
docker compose exec rabbitmq rabbitmqctl list_queues
```

### Производительность

**Синхронный режим** (текущий по умолчанию):
- ~10-50 файлов/сек (зависит от размера файлов)
- Для 2 ТБ (~10,000 файлов): ~3-17 минут

**Асинхронный режим** (4 worker'а):
- ~40-200 файлов/сек (4× быстрее)
- Для 2 ТБ (~10,000 файлов): ~50 секунд - 4 минуты

**Асинхронный режим** (8 worker'ов):
- ~80-400 файлов/сек (8× быстрее)
- Для 2 ТБ (~10,000 файлов): ~25 секунд - 2 минуты

### Переключение между режимами

**Синхронный режим** (по умолчанию):
- Используется `SynchronousMessageBus`
- Все обрабатывается сразу, без очереди
- Подходит для небольших объемов

**Асинхронный режим**:
- Используется настоящий Symfony Messenger с Redis/RabbitMQ
- Сообщения попадают в очередь
- Требуется запуск worker'ов для обработки
- Подходит для больших объемов данных

### Текущая реализация

⚠️ **Важно**: Сейчас в `index.php` используется `SynchronousMessageBus`, который обрабатывает все синхронно.

Для включения асинхронного режима нужно:
1. Заменить `SynchronousMessageBus` на настоящий Symfony Messenger MessageBus
2. Настроить транспорт (Redis/RabbitMQ)
3. Запустить worker'ы для обработки очереди

Инфраструктура уже готова:
- ✅ Конфигурация Messenger (`config/packages/messenger.yaml`)
- ✅ Redis/RabbitMQ в Docker Compose
- ✅ Worker сервис в Docker Compose
- ✅ Все команды и события маршрутизируются в `async` transport
