# Модуль массовой загрузки в Google Photos

## Описание

Модуль для надежной массовой загрузки больших объемов медиафайлов (до 2 ТБ) в Google Photos с соблюдением всех API-квот, возобновляемостью после сбоев и гарантией полноты загрузки.

## Возможности

- ✅ **Resumable Upload** - возобновляемая загрузка больших файлов чанками
- ✅ **Batch Processing** - пакетное создание медиа-элементов (до 50 файлов)
- ✅ **Дедупликация** - автоматическая проверка уже загруженных файлов
- ✅ **Сжатие** - автоматическое сжатие изображений и видео при необходимости
- ✅ **Метаданные** - передача даты съемки (приоритет: имя файла → EXIF → mtime)
- ✅ **Возобновляемость** - продолжение с места остановки после перезапуска
- ✅ **Блокировка** - предотвращение параллельного запуска нескольких экземпляров
- ✅ **Обработка квот** - автоматическая пауза при исчерпании квот и возобновление
- ✅ **Обработка истечения** - автоматическая переинициализация истекших resumable сессий
- ✅ **Частичные ошибки** - корректная обработка частично успешных батчей

## Требования

- PHP 8.4+
- Composer
- Доступ к Google Photos API (OAuth 2.0 токен)
- База данных (SQLite/PostgreSQL через Doctrine DBAL)

## Настройка

### 1. Установка зависимостей

```bash
composer install
```

### 2. Настройка переменных окружения

Создайте файл `.env` или установите переменные окружения:

```bash
# Google Photos API
GOOGLE_PHOTOS_ACCESS_TOKEN=your_access_token_here
GOOGLE_PHOTOS_ALBUM_ID=optional_album_id  # Опционально, для загрузки в конкретный альбом
```

### 3. Инициализация базы данных

```bash
php bin/console google-photos:upload --init-schema
```

Это создаст необходимые таблицы:
- `google_photos_upload_jobs` - состояние загрузки файлов
- `google_photos_upload_batches` - состояние батчей
- `google_photos_quota_status` - отслеживание квот
- `distributed_locks` - блокировки для предотвращения параллельного запуска

## Использование

### Сканирование файлов и создание задач загрузки

```bash
php bin/console google-photos:upload --source=/path/to/files --scan-only
```

Эта команда:
- Сканирует указанную директорию
- Извлекает метаданные (дата, размер, тип)
- Создает задачи загрузки в БД
- Пропускает уже загруженные файлы (по hash)

### Запуск загрузки

```bash
php bin/console google-photos:upload
```

Эта команда:
- Запускает оркестратор загрузки
- Обрабатывает файлы последовательно (один за раз)
- Собирает батчи до 50 файлов
- Автоматически обрабатывает квоты и ошибки
- Сохраняет прогресс после каждого шага

### Комбинированный запуск (сканирование + загрузка)

```bash
php bin/console google-photos:upload --source=/path/to/files
```

## Процесс работы

1. **Сканирование**: Файлы сканируются, извлекаются метаданные, создаются UploadJob
2. **Загрузка файлов**: Каждый файл загружается через Resumable Upload чанками
3. **Сбор батчей**: До 50 uploadToken собираются в батч
4. **Создание медиа-элементов**: Батч отправляется через `batchCreateMediaItems`
5. **Обработка ошибок**: При ошибках 429 - пауза, при 4xx - экспоненциальная задержка

## Обработка квот

При исчерпании квот (ошибка 429):
- Все текущие задачи переводятся в состояние PAUSED
- Записывается время сброса квоты
- Система автоматически возобновит работу после сброса (24 часа)

## Возобновление после перезапуска

Система автоматически:
- Находит незавершенные загрузки
- Продолжает с места остановки (по uploaded_bytes)
- Проверяет истекшие resumable сессии
- Возобновляет незавершенные батчи

## Мониторинг

Все события логируются:
- Начало/конец загрузки файла
- Прогресс загрузки (каждые 10 МБ)
- Создание батчей
- Обработка батчей
- Ошибки и паузы

Логи сохраняются в `var/log/` с детальной информацией.

## Ограничения Google Photos API

- Суточный лимит запросов: 10,000/день
- Суточный лимит медиа-байтов: ~75 ГБ/день
- Максимум элементов в batchCreate: 50
- Размер изображения: JPEG до 75 МП, PNG до 200 МП
- Размер видео: до 10 ГБ
- Resumable URI срок действия: ~1 неделя

## Переменные окружения

| Переменная | Описание | Обязательно |
|------------|----------|-------------|
| `GOOGLE_PHOTOS_CREDENTIALS_PATH` | Путь к файлу `credentials.json` из Google Cloud Console | Да (для авторизации) |
| `GOOGLE_PHOTOS_FULL_ACCESS` | Запросить полный доступ (photoslibrary) вместо appendonly | Нет (по умолчанию: false) |
| `GOOGLE_PHOTOS_ACCESS_TOKEN` | OAuth 2.0 access token (опционально, fallback если нет refresh token) | Нет |
| `GOOGLE_PHOTOS_ALBUM_ID` | ID альбома для загрузки (опционально) | Нет |

## Авторизация через OAuth 2.0

Система использует официальную библиотеку [Google Auth Library for PHP](https://github.com/googleapis/google-auth-library-php) для работы с OAuth 2.0.

### Шаг 1: Настройка Google Cloud Console

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/)
2. Включите **Google Photos Library API** для вашего проекта
3. Перейдите в **APIs & Services > Credentials**
4. Создайте **OAuth 2.0 Client ID**:
   - Application type: **Web application** или **Desktop application**
   - Authorized redirect URIs: добавьте ваш redirect URI (например, `http://localhost:8080/oauth/callback`)
5. Скачайте файл **credentials.json** (кнопка "Download JSON")

### Шаг 2: Настройка credentials.json

1. Сохраните скачанный файл `credentials.json` в директории на хосте (например, `/home/user/.config/google-photos/credentials.json`)
2. Добавьте путь к **директории** (не к файлу!) в `.env`:

```bash
# Путь к директории на хосте, где лежит credentials.json
GOOGLE_PHOTOS_CREDENTIALS_DIR_HOST=/home/user/.config/google-photos
```

**Важно:** 
- Указывайте путь к **директории**, а не к файлу
- Файл должен называться `credentials.json` (именно так!)
- Файл `credentials.json` содержит секретные данные - не коммитьте его в git!
- Директория будет смонтирована в контейнер как `/var/www/html/config/credentials`
- После изменения переменной перезапустите контейнеры: `make down && make up`

### Шаг 3: Авторизация приложения

1. Запустите команду авторизации:

```bash
php bin/console google-photos:authorize
```

2. Команда покажет URL для авторизации. Откройте его в браузере
3. Войдите в свой Google аккаунт и предоставьте разрешения
4. После авторизации Google перенаправит вас на redirect URI с параметром `code`
5. Скопируйте код из URL и выполните:

```bash
php bin/console google-photos:authorize --code=YOUR_AUTHORIZATION_CODE
```

6. Токены будут сохранены в базе данных автоматически

### Области доступа (Scopes)

По умолчанию запрашивается область `photoslibrary.appendonly` (только загрузка). Для полного доступа используйте:

```bash
php bin/console google-photos:authorize --full-access
```

Это запросит область `photoslibrary` (полный доступ: загрузка, создание альбомов и т.д.).

### Автоматическое обновление токенов

Система автоматически обновляет access token при его истечении используя refresh token. Вам не нужно вручную обновлять токены - это происходит прозрачно при каждом API запросе.

## Получение Access Token (альтернативный способ)

Если вы предпочитаете получить токен вручную (например, через Google OAuth Playground), вы можете установить его через переменную окружения:

```bash
GOOGLE_PHOTOS_ACCESS_TOKEN=your_token_here
```

**Примечание:** Access token истекает через ~1 час. Для длительной работы рекомендуется использовать OAuth flow с refresh token.

## Архитектура

Модуль следует принципам Hexagonal Architecture:

- **Domain Layer**: UploadJob, UploadBatch, ResumableSession (Aggregate Roots)
- **Application Layer**: UploadOrchestrator, FileScanner, ResumableUploadService, BatchProcessor
- **Infrastructure Layer**: Repositories, GooglePhotosApiClient, Compressors, QuotaTracker

## Устранение неполадок

### Ошибка "Another orchestrator instance is already running"

Это нормально - только один экземпляр может работать одновременно. Дождитесь завершения текущего процесса или проверьте, не запущен ли он в другом терминале.

### Ошибка "Quota exceeded"

Система автоматически приостановит работу и возобновит после сброса квоты (24 часа). Можно проверить статус квот в таблице `google_photos_quota_status`.

### Ошибка "Session expired"

Если resumable сессия истекла (через ~1 неделю), система автоматически начнет загрузку заново. Прогресс будет потерян, но файл будет загружен полностью.

### Файлы не загружаются

Проверьте:
1. Правильность access token
2. Наличие прав доступа к Google Photos API
3. Логи в `var/log/` для детальной информации об ошибках
